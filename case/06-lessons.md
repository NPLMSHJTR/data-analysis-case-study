# 06 可复用经验总结

> 这一篇把前五篇的东西压缩成可以直接拿去用的清单。

## 一、六条最核心的经验

如果只能带走六条，带这六条。

### 1. 先怀疑结果，再相信结果

这个项目里八个问题，有六个是「不报错、看起来合理、必须主动怀疑才能发现」的。

**具体做法**：每跑出一个结果，问三个问题：

- 这个数量级对吗？（12,828 条评论，A 类 11,562 条，占 90%——合理，因为大部分人写评论是认真的）
- 这个分布形状对吗？（如果 1 星评论的情感分中位数是 0.93，一定是工具错了）
- 如果换个方法，结论会变吗？（五组权重下前十重合 6—10 部，说明「进前十」稳、「第几名」不稳）

**具体技巧**：分组看。一个总体的相关系数是 0.0901，看不出问题；按星级分组看中位数，问题立刻暴露。

**更进一步的技巧：能用一行代码验证的假设，不要凭印象。**
我在问题 3 里犯的错就是典型——凭印象认定「验证集里全是长文本，回退不会触发」，
实测发现 112/300 条是短文本，回退改变了 84 条判定。印象和事实差了很远。

### 2. 边界比方法更重要

项目开始时花在「确认数据拿不到」上的时间，比写采集代码的时间更值钱。

**具体做法**：动手之前先写一张这样的表，贴在显眼的地方：

| 我要什么 | 我拿到了什么 | 缺口 | 这个缺口让哪些结论不能下 |
|---|---|---|---|
| 250 部影片全部评论 | 141 部的 12,828 条 | 109 部无评论 | 所有评论结论不能外推到整体 |
| 历史榜单对比 | 只有一个时点 | 无第二时点 | 不能谈任何趋势、变化 |
| 版权与票房 | 无 | 全部缺失 | 推荐只停在内容层面 |

这张表的价值在于：**它把「不能做什么」写在了前面，避免你写了一半才发现结论站不住。**

### 3. 标签不能从被检验的变量里来

情感模型的准确率可以从 69% 提到 90%，只要用星级当训练标签。但这样做 Q4 就废了。

**检查方法**：画出你研究问题的因果链，看标签在链条的哪一端。

```
星级 ──→ 训练情感模型 ──→ 情感分 ──→ 比较「星级 vs 情感」  ← 重言式，无信息
星级 ────────────────→ 情感分（独立判定）──→ 比较  ← 有信息
```

**这条经验的适用范围**：只在「研究问题涉及该变量」时成立。如果只是做情感分类，
用星级训练完全合理。红线不是普遍规则，是特定问题下的约束。

### 4. 排除优先于归类

这是问题 7 的教训，也是数据清洗的通用原则。

**判断顺序应该是**：

```
1. 这条记录可信吗？（结构校验：字段对不对、值域合法吗）
2. 这条记录和主题相关吗？（广告、无关内容）
3. 这条记录是重复的吗？
4. 这条记录有多少信息？（长度、要素词）
```

顺序错了会出问题：如果先做第 4 步，那 255 条字段错位的记录会被判成「信息少」，
而不是「不可信」。两者后续处理完全不同。

**代码里的落点**：把结构校验写成第一个 `if`，不是最后一个 `else`。

### 5. 中间产物要分两类管理

| 类型 | 判断标准 | 处理 |
|---|---|---|
| 可重建 | 跑一次代码就能重新生成 | 不入版本控制，节省体积 |
| 不可重建 | 人力产出，代码无法代劳 | **必须入库，还要备份** |

这个项目里唯一不可重建的是 `manual_validation.csv`（300 条人工标注，82 KB）。
它决定了整个方法对比实验有没有基准。

**推广到别的项目**：
- 爬虫的原始响应 → 不可重建（对方页面会变）→ 存
- 清洗后的数据 → 可重建 → 不存
- 人工标注 → 不可重建 → 存 + 备份
- 模型训练好的权重 → 视情况（能重训就不存，训练成本极高就存）

### 6. 报告里的数字必须自动填充

`report_generator.py` 有 2,440 行，绝大部分是排版和数字填充。这个长度不好看，但它换来一件事：

**改任何中间结果，重跑一次报告，55 页里的所有数字自动同步。**

手工填数字的项目，改一次参数就要在几十页里找一遍所有受影响的数字，漏一个就是错。
更糟的是这种错误无法通过测试发现——数字看起来都很正常，只是过时了。

## 二、可以直接抄走的检查清单

### 项目启动阶段

- [ ] 数据能不能拿到？先发一个请求试，别先写代码
- [ ] 拿不到的原因是什么？访问控制 / 网络 / 不存在，三种情况处理方式完全不同
- [ ] 列出「我要什么 / 拿到什么 / 缺口 / 影响哪些结论」四列表
- [ ] 有没有第二个时间点？没有就明确标注不做趋势分析
- [ ] 研究问题的因果链画出来，检查标签有没有泄漏

### 写代码阶段

- [ ] 每一阶段的输入、输出、失败后果写清楚
- [ ] 失败不中断可独立完成的阶段
- [ ] 分类字段加断言：`assert df['类型'].isin(候选集+['其他']).all()`
- [ ] 多个不同量纲的指标相加前，先标准化
- [ ] 字段名带口径（`验证集保留数` 而不是 `保留数`）
- [ ] 一次性外部数据获取，把原始响应存下来

### 验证阶段

- [ ] 每跑出一个结果，问「这个数量级对吗」
- [ ] 分组看分布，不要只看总体指标
- [ ] 反算验证：同一张表里的数字要能互相算出来
- [ ] 改了机制之后，确认它实际影响了哪些样本
- [ ] 做敏感性分析：换几组参数，看结论稳不稳

### 交付阶段

- [ ] 每个数字能在结果文件里找到出处
- [ ] 明确标注「哪些是算出来的，哪些是我判断的」
- [ ] 不可重建的文件有备份
- [ ] 全流程能从零跑通一遍

## 三、这个项目的做法可以搬到哪

### 直接适用

| 场景 | 为什么适用 |
|---|---|
| 文本数据的质量筛选 | 双维度（内容有效性 × 元数据一致性）的框架通用 |
| 用户评论 / 工单 / 反馈分析 | 短文本、有评分或标签、需要筛掉噪声 |
| 任何「评分与文字并存」的数据 | 评分与文本的偏差本身就是研究对象 |

### 需要改造

| 场景 | 要改什么 |
|---|---|
| 图像 / 音频数据 | 第一维度要换成「可辨识度」「清晰度」，不是文本长度 |
| 没有元数据标签的数据 | 第二维度不存在，退化为单维度，但「分级处置」仍可用 |
| 数据量小（几百条） | 不要用统计检验下结论，改为逐条人工判断 |
| 需要实时处理 | 14 阶段批处理不适合，要改为流式 |

### 不适用

| 场景 | 为什么 |
|---|---|
| 需要因果推断的问题 | 本项目只做相关分析，没有识别策略 |
| 需要预测的问题 | 没有训练预测模型，也没有留出测试集 |
| 涉及隐私或个人画像 | 本项目只做到影片层面，不涉及用户画像 |

## 四、三个反直觉的结论

这三条和常规做法相反，但在本项目里被验证有效。

### 反直觉一：准确率不是越高越好

情感模型准确率 69.33%，被否掉的 TF-IDF + 逻辑回归是 68.00%，看起来差不多。
但后者的宏 F1 只有 0.4060——**它基本只会判「正面」**。

这种模型在总体准确率上不难看，但在分析「负面评论有什么特征」时会全面失效。

**教训**：看分类指标要同时看宏平均 F1，不能只看准确率。类别不平衡时，准确率会骗人。

### 反直觉二：把人工标注放在中间，不是最后

常规做法是「先跑通主线，最后补验证」。实际做下来，标注必须放在中间。

原因：**标注表里有哪几列，就定义了你要评价哪几件事。** 这是设计决策，不是验收步骤。

放到最后做，会发现标注字段不全（只标了内容质量，没标情感方向）、样本有偏（只标了短评论），
两处都要重做，而标注是纯人力工作。

### 反直觉三：承认做不了，比硬做一个结论更有价值

Q2 要求找「占比变化最大的组合」，但只有一个时点。

硬做的方法很多：把「当前榜单里 1980 年代动画占 31.2%」写成「动画在 80 年代崛起」。
这个数字很漂亮，写进报告很好看。

但它是把筛选结果当成了原始分布——当前榜单是几十年筛选的产物，不是当年的创作结构。

**标注「数据不足」看起来是没做完，实际上是不给读者一个错误结论。**

## 五、如果重做一次

### 会改的三件事

1. **把口径写进字段名。** 问题 8 那个「保留评论数」的矛盾，如果字段叫
   `验证集保留数` 和 `全量保留数`，写下的那一刻就会被发现。

2. **标注从第一天开始。** 不是「最后补一个验证集」，而是「先定标注表，再写代码」。
   标注表定义了什么叫「对」，它应该在前，不该在后。

3. **阈值在独立测试集上选。** 现在的 0.55 / 1.10 和回退阈值 0.80 / 0.20 都在同一份
   300 条验证集上试出来的，存在样本内乐观偏差。更好的做法是留一份独立测试集，
   只在最终评估时用一次。

### 不会改的三件事

1. **不用星级训练情感模型。** 这是红线，改了就失去 Q4。
2. **不用 14 个阶段的流水线结构。** 失败隔离的收益远大于「不能任意跳步」的不便。
3. **报告数字自动填充。** 2,440 行的代价，换来的是数字永不过时。

## 六、这套方法的天花板

诚实地讲，这个项目的方法有几处上限：

**上限一：所有结论都是相关性的，不是因果的。**
「星级与文本弱相关（r = 0.2404）」说明两者有关联，但不能说明「是星级影响了文本」
还是「文本影响了星级」还是「第三个因素同时影响了两个」。本项目没有识别策略。

**上限二：情感模型准确率 69.33%，意味着约三成判定是错的。**
所有基于情感分的下游结论（Q3 的指数、Q4 的偏差率）都带着这个误差。
虽然方向性结论（低星文本偏正面、高星文本偏负面）在多种检验下一致，
但具体数值不能当精确值用。

**上限三：一致性判定的准确率从未被直接验证。**
人工标注只提供了「内容是否有效」和「情感方向」，没有提供「这条评论的星级与文本是否自洽」的独立判断。
所以「严重矛盾 878 条」这个数字，衡量的是规则判定结果，不是真实矛盾的数量。

**上限四：覆盖率 56.4%。**
141 部有评论，109 部没有。这两组影片是否有系统性差异（比如冷门片评论更少），本项目没有检验。

## 七、写在最后

这个项目最初的样子是一份课程作业。做到中途发现，真正难的不是「算出来」，
而是「算出来的东西能不能站得住」。

八个问题里，没有一个是因为代码写错。全部是判断错了：

- 判断错了数据来源的合法性（问题 1）
- 判断错了工具的适用性（问题 2）
- 判断错了机制的作用位置（问题 3）
- 判断错了字段的完整性（问题 4）
- 判断错了尺度的可比性（问题 5）
- 判断错了标签的来源（问题 6）
- 判断错了处理的优先级（问题 7）
- 判断错了字段的口径（问题 8）

**代码只负责执行判断，判断错了，代码跑得越顺，错得越远。**

所以这套方法最核心的一条，还是第一句：先怀疑结果，再相信结果。
