# 02 整体设计思路

> 设计的本质不是把功能列全，而是决定哪些事不做、哪些事分开做、哪些事必须先做。

## 一、先看一张图

整个项目的数据流是这样的：

```
                     ┌─────────────────────────────────────────┐
   榜单页 ──────────→│ 01 采集   250 部影片 + 10 个 HTML 快照   │

                     └────────────────┬────────────────────────┘
                                      ↓
                     ┌─────────────────────────────────────────┐
                     │ 02 清洗   去重 / 结构校验 / 文本规整     │
                     └────────────────┬────────────────────────┘
                                      ↓
        ┌─────────────────────────────┴──────────────────────────┐
        │                    03 第一维度：内容有效性              │
        │            A 有效 / B 低信息量 / C 无关 / D 重复         │
```

这张图有三个地方值得停下来看：为什么有两个维度、为什么阶段是这样切的、为什么报告放在最后。

## 二、核心结构：为什么是「两个维度」而不是一列标签

### 常规做法的问题

最常见的做法是给每条评论打一个标签：有效 / 无效。有效留下，无效删掉。

这个设计有一个隐藏假设：**评论的质量是一个单一的量，可以从好排到坏。**

但实际数据里，质量和一致性是两个独立的问题：

| | 星级与文本一致 | 星级与文本矛盾 |
|---|---|---|
| **内容有效** | 正常样本，可用 | **最有价值的样本**：五星配差评、一星配好评 |
| **内容低信息量** | 「好看」配五星，无分析价值但有态度 | 「哈哈哈哈」配一星，同样是纯表态 |

右下角那个格子是关键。如果只用一列标签，这类样本要么被当成「有效」混进内容分析，
要么被当成「无效」直接删掉。两种处理都会丢失信息：

- 混进去 → 情感均值被自相矛盾的文本污染
- 删掉 → 丢掉了研究「星级与文本偏差」的全部素材，Q4 就无从谈起

**所以必须分成两个维度，让这两个问题各自被回答。**

### 两个维度分别管什么

**第一维度（内容有效性）** 回答：这条文本里有没有可分析的内容？

六类标签，互斥，有明确优先级 `X → C → D → E → B → A`。

优先级的设计依据是「**排除优先于归类**」：

- 字段整体错位（X）→ 文本本身不可信，此时讨论内容有没有意义是无意义的
- 是广告（C）→ 与影片无关，此时讨论情感也是无意义的
- 是同片重复副本（D）→ 副本不单独计价，避免同一段文字被算两次

顺序错了会出问题。这一点在实施中真的踩到了：第一版结构校验只认「空文本」，
结果 255 条字段整体错位的记录被内容规则重新判成了「B 类低信息量」——
**「不可信」被当成了「信息少」**，X 类从 258 掉到 3。这是后话，详见 [05 问题记录](05-problems.md)。

**第二维度（星级一致性）** 回答：文本表达的情感，和用户打的星，是否自洽？

```
star_norm = (rating − 3) / 2          1星 = −1，3星 = 0，5星 = +1
gap       = star_norm − sentiment_score
```

四个档位：

| 档位 | 阈值 | 含义 |
|---|---|---|
| 一致 | \|gap\| < 0.55 | 打高分的说好话，打低分的说坏话 |
| 轻度不一致 | 0.55 ≤ \|gap\| < 1.10 | 有偏差但不极端，如四星里带一句「结尾略仓促」 |
| 严重矛盾 | \|gap\| ≥ 1.10 | 五星配通篇差评，这类要单独隔离 |
| 无法判定 | 情感置信度 < 0.25 | 模型没把握，不强行归类 |

阈值 0.55 / 1.10 不是拍脑袋。0.40 会把「四星里一句轻微抱怨」误判成矛盾，
0.80 会漏掉「五星配通篇差评」，0.55/1.10 在 300 条人工验证集上误判最少。

### 两个维度怎么合成处置

交叉之后不是简单取交集，而是一张处置矩阵：

| 内容有效性 | 一致性 | 处置 | 进入哪类分析 |
|---|---|---|---|
| A 有效 | 一致 | `content` | 内容分析 + 情感统计 |
| A 有效 | 轻度不一致 | `content` | 内容分析，标记不一致 |
| A 有效 | 严重矛盾 | `mismatch_only` | **只进矛盾样本表**，不进情感均值 |
| A 有效 | 无法判定 | `manual` | 待人工判断 |
| B 低信息量 | 任意 | `sentiment` | **只进情感统计**，不进内容分析 |
| C/D/E/X | 任意 | `excluded` | 排除 |

这张表最重要的一行是「A + 严重矛盾 → 只进矛盾表」。它体现了一个原则：
**隔离而不是删除。** 数据要保留，但要说清楚它被排除在哪个统计之外。

## 三、为什么切成 14 个阶段

### 切分依据

切分的依据不是「功能模块」，而是**失败影响范围**。

| 阶段 | 输入 | 输出 | 失败后果 |
|---|---|---|---|
| 01 采集 | 榜单页 / 公开数据集 | `top250_raw.csv`、`reviews_raw.csv` | **流程终止** |
| 02 清洗 | 原始评论 | `reviews_cleaned.csv` | 后续全废 |
| 03 内容分级 | 清洗结果 | `reviews_labeled.csv` | 后续全废 |
| 04 情感分析 | 分级结果 | `reviews_scored.csv` | 后续全废 |
| 05 一致性 | 分级 + 情感 | `reviews_dual.csv` | Q4 与指数受影响 |
| 06 方法对比 | 双维度 + 人工标注 | `method_comparison.csv` | 报告第四章缺数据 |
| 07 Q1/Q2 | 影片数据 | `q1_*.csv`、`q2_*.csv` | 第五、六章缺数据 |
| 08 Q3 | 双维度结果 | `q3_*.csv` | 第七、九章受影响 |
| 09 Q4 | 情感结果 | `q4_*.csv` | 第八章缺数据 |
| 10 Q5 | Q3 + 市场数据 | `q5_*.csv` | 第九章缺数据 |
| 11 图表 | 全部结果 | 18 张 PNG | 报告缺图 |
| 12 截图 | 源码 | 10 张 PNG | 附录缺图 |
| 13 Word | 全部结果 | `.docx` | PPT 仍可生成 |
| 14 PPT | 全部结果 + 讲稿 | `.pptx` | — |

**关键设计：每个阶段失败不中断后续可独立完成的阶段。**

只有 01 采集失败会终止流程（没有影片数据，什么都做不了）。其余阶段失败只影响下游，
其他分支照常跑完。这样一次运行能拿到尽可能多的信息，而不是遇到第一个错就全停。

### 依赖关系的表达

```
01 → 02 → 03 → 04 → 05 → 06
                  ↓
                  08 → 10 → 11 → 13 → 14
                  ↓
                  09 ────────┘
07 ────────────────────────┘
```

这条链决定了一件事：**改 04 情感分析，05 之后全部要重跑；只改 13 Word 的排版，重跑 13 就行。**

如果不把这条链写下来，改一个参数后重跑整条流程要 36 秒，看着不长，但调试时一天要跑几十次；
更麻烦的是容易漏跑，改了下游没重跑，报告里的数字和表就对不上了。

### 为什么报告放在最后

13 和 14 阶段（Word、PPT）放在流程末尾，不是因为它们最后完成，而是因为**它们不允许手工填数字**。

报告里所有的数值都由 `collect()` 从结果文件读取后填入。这样做的代价是报告生成代码很长
（`report_generator.py` 有 2,440 行），收益是：**改任何一个中间结果，重跑一次报告，数字自动同步。**

手工填数字的项目，改一次参数就要在几十页文档里找一遍所有受影响的数字，漏一个就是错。
这个代价不值得省。

## 四、三个关键取舍

### 取舍一：情感模型用规则，不用预训练

| 方案 | 准确率 | 为什么不用 / 用 |
|---|---|---|
| 词典 + 规则 | 69.33% | **最终采用**：可追溯到具体词，能解释成因；不依赖下载权重 |
| 朴素贝叶斯（snownlp） | 64.67% | 作为回退的极端值判定，不单独使用 |
| TF-IDF + 逻辑回归 | 68.00% | 准确率尚可但宏 F1 仅 0.4060，严重偏向多数类 |

准确率不是唯一标准。**宏 F1 0.4060 意味着模型基本只会判「正面」**，
这种模型即使总体准确率 68%，在分析「负面评论特征」时会全面失效。

更重要的是第一条：情感判定**不能使用星级作为训练标签**。这是判断二，是整个项目的红线。

### 取舍二：指数用「排名」比较，不用「原始分数」比较

被低估指数的原始设计是把评分线性映射到 [−1, 1]：9.5 分 → +0.9。

问题在于，中文短评的平均情感分通常只有 0.2—0.4。两把尺子量纲完全不同，
相减的结果恒为负——**指数退化成「评分越高越被高估」**，前十名全是 9.3 分以上的片子。

修法不是调整映射区间，而是让两个量在同一把尺子上比较：**S 和 R 各自做样本内 Z 标准化后再相减。**
比较发生在「排名」层面，文本情感排名高于评分排名，gap 才为正。

同时保留原始刻度差 `gap_raw` 供直观核对，但它不参与计算。

### 取舍三：中间产物分两类，一类入库一类不入库

| 类型 | 例子 | 处理 | 理由 |
|---|---|---|---|
| 可重建 | `reviews_labeled.csv`（7.6M）、`reviews_dual.csv`（9.0M） | 不入库 | 跑一次 `main.py` 就能重新生成 |
| 不可重建 | `manual_validation.csv`（82K，300 条人工标注） | **必须入库** | 由人逐条阅读评论填写，代码无法代劳 |

这条界线看起来是仓库管理问题，其实是**数据价值观问题**：什么可以被重新计算，什么一旦丢失就永久失去。

`manual_validation.csv` 是这个项目里唯一不能靠代码重跑得到的东西。它丢了，
方法对比实验就没有基准，报告第四章和 PPT 第 10 页的所有数字都失效。

所以它不仅有备份（`.backup.csv`），还额外被写进文档反复提醒「千万别删」。

## 五、这套设计有什么代价

任何设计都有代价，不写代价的设计说明是不完整的。

**代价一：双维度让流程变长。** 从「一个标签」变成「两个标签加一张矩阵」，代码量、调试成本、
文档篇幅都增加了。收益是能区分「有效但矛盾」这类样本，但如果你的数据里这类样本很少，
双维度就是过度设计。

**代价二：不用星级训练，准确率上限被压低。** 69.33% 的准确率在今天的标准下不高。
如果研究问题不涉及「星级与文本是否一致」，这条红线就没必要，用星级训练能拿到更高准确率。

**代价三：报告自动生成，代码变得很长且难改。** `report_generator.py` 2,440 行，
改版式要读懂大段排版逻辑。如果报告只生成一次，手工排版更快。

**代价四：14 个阶段有依赖顺序，不能任意跳跃。** 调试时必须知道改的东西影响谁。
好处是失败隔离，坏处是不能随性地「只跑最后一步」。

## 六、如果重做一次，我会改什么

1. **把「保留数」这类字段的口径写进字段名。** 现在的 `method_comparison.csv` 里
   「保留评论数」填的是验证集子集计数（258/181），而同一行的「占全量比例」是 98%/91.14%，
   两者矛盾。根因是代码在验证集子集上算指标，却把子集计数填进了全量表。
   如果字段叫 `验证集保留数` 或 `全量保留数(12571)`，这个错误一眼就能看见。详见 [05](05-problems.md)。

2. **人工标注从第一天就开始做，而不是最后补。** 300 条标注是整个项目里最耗时、
   最不可替代的环节，但它同时也是唯一能验证方法是否有效的东西。越晚做，越可能发现
   前面设计有问题却来不及改。

3. **阈值选择应该在独立的验证集上做。** 现在的 0.55/1.10 和回退阈值 0.80/0.20
   都是在同一份 300 条验证集上试出来的，存在样本内乐观偏差。这一点已在
   `docs/methodology.md` 里声明，但更好的做法是留一份独立测试集。
