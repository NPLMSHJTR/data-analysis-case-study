# 05 遇到的问题及解决方案

> 这一篇是全套文档里最实用的部分。八个问题都真实发生过，都写清了「现象、根因、修法、代价」。

八个问题的共同点是：**代码没报错，结果看着还挺整齐。** 它们只能靠盯着结果问一句「这合理吗」发现。

按发现难度排序，从最容易看见的排到最隐蔽的。

## 问题 1：短评页一律跳安全验证

### 现象

榜单页抓取正常，返回 200 和完整 HTML。但请求影片详情页和短评页时：

```
302 → https://sec.douban.com/...
```

换 UA、加 Referer、加 Cookie 都一样。

### 根因

豆瓣对未登录访问详情页和短评页有访问控制，跳转到安全验证页是它设计的正常行为，不是 bug。

### 方案对比

| 方案 | 可行性 | 是否采用 | 理由 |
|---|---|---|---|
| 模拟登录（提交账号密码） | 技术可行 | **否** | 需要真实账号，且涉及账号安全 |
| 破解验证码 / 验证页 | 技术可行 | **否** | 明确违反访问控制，数据来源不正当 |
| 提高请求频率反复重试 | 不可行 | 否 | 只会更快触发限制 |
| **改用公开数据集** | 完全可行 | **是** | 数据来源合法，可追溯 |

### 采用的方案

改用 GitHub 公开仓库 `xiaobing0222/Douban-Movie-Review-Dataset`（2024-04 发布），
字段为 `time / uname / comment / star / title / support / sentiment_score`，
内容是抓取时的豆瓣页面原始短评。

使用时做了两处处理：

1. **不使用数据集自带的情感分** `sentiment_score`。那是第三方模型的产物，口径不明，
   用它等于把别人的判断当成自己的结果。情感分析完全独立重做。
2. **用户名做 MD5 哈希脱敏**，避免把用户 ID 散布出去。

### 代价（这一条最重要）

覆盖率只有 **56.4%**：148 个影片文件中 141 部能与当前榜单匹配，当前榜单另有 109 部无评论。

这个缺口不是免责声明，它改变了结论的适用范围：

> 所有涉及评论的结论，都不能外推到 Top250 整体。

这句话在报告里出现了多次，因为每写一个基于评论的结论，都必须提醒读者它的边界在哪。

### 可迁移的经验

**数据拿不到时，先问「为什么拿不到」。** 如果是访问控制，那正确答案是换数据源，
不是绕过它。绕过能拿到数据，但会永久损害结论的可信度——而这个损失事后无法弥补。

## 问题 2：情感模型把 71% 的一星评论判成正面

### 现象

最初的方案是用现成的通用情感工具 snownlp 直接跑。跑出来的结果：

- 星级与文本情感分的 Spearman 相关系数 = **0.0901**（p = 2.73e-22）
- 这个数字低到几乎等于「不相关」。但它其实还有统计显著性，因为样本有 11,562 条

但拿几条一星评论人工看，明显是差评。于是去查各星级的情感分分布：

| 星级 | 评论数 | snownlp 情感中位数 |
|---|---:|---:|
| 1 星 | 200 | 0.9298 |
| 2 星 | 376 | 0.9920 |
| 3 星 | 1,218 | 0.9945 |
| 4 星 | 3,537 | 0.9992 |
| 5 星 | 6,231 | 0.9995 |

**一星评论的情感中位数是 0.9298。** 而且 1 星里有 71.0% 被判为正面（> 0.6）。

### 根因

这不是数据的问题，是工具的问题。snownlp 的训练语料是电商评论，中文电影短评里的
「烂」「无聊」「拖沓」在它的语境里权重很低，而「好看」「精彩」这类词一出现，
分数就被拉高。加上短评论常常只有几个字，模型没有足够上下文。

**关键认识：那个 0.0901 不是「用户行为」，而是「工具的分辨力极限」。**
用一个连一星和五星都分不开的尺子去量差异，量出来当然是零。

### 修法

改为自建领域情感词典 + 规则，核心组件：

| 组件 | 规模 |
|---|---|
| 正面词典 | 约 190 条，权重 0.8—1.8 |
| 负面词典 | 约 170 条，权重 0.8—1.8 |
| 否定词 | 25 条（含「不怎么」「谈不上」双字形式） |
| 程度副词 | 20 条，系数 1.2—1.8 |
| 转折词 | 8 条 |

评分公式：

```
raw   = Σ (weight × polarity × negation_factor × degree_factor × turn_weight)
score = tanh(raw / sqrt(n_hits + 1) / 1.6)
```

`tanh` 压缩避免长文本分数爆炸，`sqrt(n_hits+1)` 归一避免命中数直接决定分数。

### 三个容易踩的细节

**细节一：单字「无」「非」不能列入否定表。**

「非常精彩」里的「非」不是否定；「两小无猜」里的「无」是成语成分；
「无一遗漏」是强调。列入之后会大面积误判。

**细节二：否定窗口取情感词前 3 字，不是 6 字。**

初版用 6 字，把「我不觉得这部片无聊」这种句子里无关的否定字也算了进去。
3 字窗口在验证集上表现更好。

**细节三：双重否定要单独处理。**

窗口内出现 2 个及以上短否定标记时取消反转，否则「不是不好看」会被判成负面。

### 效果与代价

| 指标 | 改进前（snownlp） | 改进后（词典+回退） |
|---|---|---|
| 与星级的 Spearman | 0.0901 | 0.1847 |
| 各星级中位数极差（2—5 星） | 0.0075 | 明显拉开 |
| 300 条验证集准确率 | 64.67% | 69.33% |

**代价**：准确率 69.33% 在今天的标准下并不高。如果改用 BERT 这类预训练模型，
准确率能上 85% 以上。但有两个理由没这么做：

1. 运行环境无法保证下载预训练权重（几百 MB，且需要联网）
2. **最关键：情感判定不能用星级训练**，否则 Q4 变成循环论证（见问题 6）

### 可迁移的经验

**相关系数接近零时，先别下「无关」的结论。** 要检查测量工具还有没有分辨力。

检查方法：分组看中位数、看分布形状、看极端值比例。这三样比一个相关系数更能说明问题。

反过来的道理也成立：如果某个工具给出很高的相关系数，也要看它是不是把同一件事量了两遍。

## 问题 3：回退机制到底提高了精度，还是只扩大了覆盖

### 现象

词典法有个明显短板：没命中任何情感词的评论会拿 0 分，被判为中性。
初版有约一半评论落在这个区间，等于大量样本无法参与一致性分析。

于是加了回退：未命中时调用 snownlp，只有当它给出极端值（> 0.80 或 < 0.20）
才采信方向，置信度上限压到 0.45。

我一开始的判断是：**「回退扩大的是覆盖，不是精度」，因为验证集上的准确率看起来没变。**

这个判断是错的。错误的过程比结论更有价值，所以完整写下来。

### 错在哪

我当时的推理是这样的：

1. 300 条验证集上，无回退准确率 61.67%，含回退 69.33%
2. 但直觉上「回退只影响未命中的短文本，验证集里全是长文本，所以回退不该被触发」
3. 于是推断这两个数字的差异来自别的因素，回退本身没起作用

第 2 步是**凭印象下的判断，没有实测**。实际查一下验证集的文本长度：

| 指标 | 实测值 |
|---|---|
| 最短文本长度 | 1 字 |
| 长度中位数 | 24 字 |
| 长度 < 10 字的条数 | **112 / 300** |

验证集里有 112 条短文本，占 37%。「全是长文本」这个前提根本不成立。

### 实测：回退确实触发了

对同样的 300 条，分别用 `use_fallback=False` 和 `use_fallback=True` 跑一遍：

| 指标 | 无回退 | 含回退 |
|---|---:|---:|
| 判定发生改变的条数 | — | **84 条** |
| 准确率 | 0.6167 | **0.6933** |
| 宏 F1 | 0.5764 | **0.6052** |
| 中性（neu）条数 | 148 | 64 |

**84 条判定被改变，准确率提高 23 条。回退既扩大了覆盖，也提高了精度。**

### 更细致的一层：变化发生在哪

把这 84 条单独拆开看，会发现它们**全部来自「原本判中性」这一类**：

| 回退前 | 回退后 | 条数 |
|---|---|---:|
| neu | pos | 75 |
| neu | neg | 9 |

这 84 条在无回退时全部是中性。回退把其中 75 条判成了正面、9 条判成了负面。

再看这 84 条的人工真值：pos 51 条、neu 26 条、neg 7 条。

也就是说，回退把一个「全判中性」的粗略状态，改成了「有方向但会出错」的状态——
**方向对了 51 条，错了 7 条，另外 26 条本该保持中性却被给了方向。**

### 净收益的算法

这里有一个容易算错的地方，我最初就算错了。

「84 条里改对 49 条、改错 35 条」，看起来净收益是 49 − 35 = 14 条。但准确率实际提高了 23 条。

差异的原因：**改错的 35 条里，有一部分在改动之前也是错的**——
原来是「该判 pos 却判了 neu」，改后变成「判了 neg」，两次都错，不构成新的损失。

正确的算法是分两组对比：

| 分组 | 条数 | 无回退时正确 | 含回退时正确 |
|---|---:|---:|---:|
| 判定发生改变 | 84 | 26 | 49 |
| 判定未改变 | 216 | 159 | 159 |
| 合计 | 300 | **185** | **208** |

185 → 208，提升 23 条。**全部来自那 84 条变化样本的净改善（26 → 49）。**

### 代价也存在

回退不是纯赚。看分类别看：

| 类别 | 精确率（无→含） | 召回率（无→含） |
|---|---|---|
| pos | 0.8583 → 0.7692 ↓ | 0.5568 → **0.8108 ↑** |
| neu | 0.4527 → 0.6406 ↑ | 0.7976 → **0.4881 ↓** |
| neg | 0.4688 → 0.4146 ↓ | 0.4839 → 0.5484 ↑ |

**正面类的召回率大幅提高（0.56 → 0.81），但中性类的召回率明显下降（0.80 → 0.49）。**

这意味着：回退倾向于给评论一个方向，哪怕它本该是中性。对「找出口碑倾向」有利，
但对「判断这条评论是否真的没表态」不利。

### 全量数据上的规模

验证集只有 300 条，回退在全量 12,828 条上的作用有多大，需要单独实测：

| 指标 | 无回退 | 含回退 |
|---|---:|---:|
| 中性（neu）条数 | 6,159（48.01%） | 1,950（15.20%） |
| 有明确方向的条数 | 6,669 | 10,878 |
| 判定发生改变 | — | **4,209 条（32.8%）** |

**近三分之一的评论因为回退而获得了方向。** 这就是为什么回退的影响必须写进报告的局限性说明——
它不是一个小修补，而是改变了三分之一样本的判定。

### 这个案例真正的教训

表面上这是一个「机制有没有生效」的问题，实际上是**两个更普遍的错误**：

**错误一：用印象代替实测。** 「验证集里全是长文本」是我凭印象说的，查一下就知道有 112 条短文本。
凡是能用一行代码验证的假设，都不该凭印象。

**错误二：把「变化条数」和「净收益」混为一谈。** 84 条变化不等于 84 条改善，
也不能用「改对减改错」算净收益，因为改动的起点可能本来就是错的。

### 可迁移的经验

**要评价一个机制的效果，必须做对照实验。** 同一批数据，开和关各跑一遍，逐条比对。

```python
p_off = [f(t, flag=False) for t in texts]
p_on  = [f(t, flag=True)  for t in texts]
changed = [i for i in range(len(texts)) if p_off[i] != p_on[i]]
```

然后**只在这批 changed 样本上看指标变化**，因为其余样本的结果完全相同，对差异没有贡献。

**如果 changed 是空的，那这个机制就是无效的**——不管总体指标看起来有没有动。

## 问题 4：主类型取首词，11 部影片从交叉表里凭空消失

### 现象

画年代×类型热力图时，图上出现了「奇幻」「传记」「冒险」「儿童」这几行，
而任务书列出的候选类型只有 11 类，这些都不在其中。

### 根因

类型字段长这样：`奇幻 冒险`、`传记 犯罪 剧情`、`儿童 喜剧 动画 奇幻 冒险`。

初版规则是取类型串的第一个词。这 11 部影片的首词不在候选集内：

| 影片 | 年份 | 类型串 | 取首词结果 |
|---|---|---:|---|
| 哈利·波特与魔法石 | 2001 | 奇幻 冒险 | 奇幻 |
| 哈利·波特与密室 | 2002 | 奇幻 冒险 | 奇幻 |
| 哈利·波特与阿兹卡班的囚徒 | 2004 | 奇幻 冒险 | 奇幻 |
| 哈利·波特与凤凰社 | 2007 | 奇幻 冒险 | 奇幻 |
| 哈利·波特与死亡圣器(上) | 2010 | 奇幻 冒险 | 奇幻 |
| 哈利·波特与死亡圣器(下) | 2011 | 奇幻 冒险 | 奇幻 |
| 猫鼠游戏 | 2002 | 传记 犯罪 剧情 | 传记 |
| 美丽心灵 | 2001 | 传记 剧情 | 传记 |
| 怪兽电力公司 | 2001 | 儿童 喜剧 动画 奇幻 冒险 | 儿童 |
| 哪吒闹海 | 1979 | 冒险 动画 奇幻 | 冒险 |
| 遗愿清单 | 2007 | 冒险 喜剧 剧情 | 冒险 |

首词分布：奇幻 6 部、传记 2 部、冒险 2 部、儿童 1 部。

这 11 部不是被归到「其他」，而是**根本没进交叉表**——因为交叉表的行是固定的 11 类，
它们的首词不在其中，就成了没有归属的孤儿。

### 修法

改为两步规则：

```
第一步：首词在 11 类候选集内 → 直接用
第二步：不在 → 按优先级取第一个命中的类型
        动画 → 纪录片 → 科幻 → 悬疑 → 犯罪 → 战争
        → 动作 → 爱情 → 喜剧 → 剧情
第三步：全不命中 → 归为「其他」
```

重算后分布：剧情 170、喜剧 24、爱情 2、动作 18、科幻 5、悬疑 3、犯罪 6、动画 15、
战争 0、纪录片 1、其他 6，合计 250 部。

### 这个修法有没有副作用

有，而且它推翻了另一个结论。

原来观察到「动画电影在 1980 年代从 0% 暴增到 31.2%」，看起来像是重大发现。
但《哪吒闹海》（1979）的类型串是「冒险 动画 奇幻」，取首词判为「冒险」，
所以 1970 年代的动画计数是 0——1980 年代一有动画，就显得像「从无到有」。

按修正后的规则：

| 区间 | 影片数 | 动画部数 | 动画占比 | 取首词口径下 |
|---|---:|---:|---:|---|
| 1970—1979 | 4 | 1 | 25.00% | 0 部 / 0.00% |
| 1980—1989 | 16 | 5 | 31.25% | 5 部 / 31.25% |
| 跳变幅度 | — | — | **+6.25 个百分点** | +31.25 个百分点 |

**「动画在 80 年代突然崛起」这个结论是被自己推翻的。** 真实的跳变只有 6.25 个百分点，
不是 31.25 个。

### 可迁移的经验

**分类字段要先确认「所有样本都能归到某一类」。** 加一行断言检查就行：

```python
assert df['主类型'].isin(CANDIDATES + ['其他']).all()
```

如果没有这一行，11 个样本会静默消失，而交叉表的合计仍然是 250——因为你的检查可能
只查了「合计对不对」，没查「有没有样本没被计入」。

## 问题 5：被低估指数前十全是 9.3 分以上的片子

### 现象

第一版指数跑出来，前十名是这样的：肖申克的救赎、霸王别姬、阿甘正传……
**全部是 9.3 分以上的片子。**

这不是「发现被低估的影片」，这是把 Top250 榜单又排了一遍。

### 根因

原始公式：

```
U = 0.50·(S − R) + 0.30·Z(H) − 0.20·Z(P)
```

其中 R 是把 10 分制评分**线性映射**到 [−1, 1]：9.5 分 → +0.9。

而中文短评的平均情感分 S 通常只有 0.2—0.4。

两把尺子的量纲完全不同：

| 影片 | R（线性映射） | S（情感分） | S − R |
|---|---:|---:|---:|
| 9.5 分片 | +0.90 | 约 0.30 | **−0.60** |
| 8.5 分片 | +0.70 | 约 0.30 | **−0.40** |

所有影片的 S − R 都是负数，而且**评分越高，负得越多**。
指数单调递减于评分，于是退化成「评分越高越被高估」。

### 修法

不要调整映射区间，而是让两个量在同一把尺子上比较：

```
S_std = Z(S)        样本内标准化
R_std = Z(R)        样本内标准化
U = 0.50·(S_std − R_std) + 0.30·Z(H) − 0.20·Z(P)
```

比较发生在「排名」层面：**文本情感排名高于评分排名，gap 才为正。**

同时保留原始刻度差 `gap_raw` 供直观核对，但它不参与计算。

### 效果

改进后前十：三块广告牌（8.7 分，U=1.7247）、血战钢锯岭（8.7）、你的名字。（8.5）、
花束般的恋爱（8.6）、疯狂的麦克斯4（8.7）……

**前十集中在 8.5—8.7 分区间。**

### 一个需要解释的后续问题

改完之后会有人问：为什么被低估的不是 9.5 分的片子？

答案是指数的尺度设计决定的：9.3 分以上的影片，R_std 本来就在样本顶端，
S_std − R_std 很难为正。**指数天然盯着「次高分区间」，而这一段正是 Top250 里最容易被忽视的。**

这是尺度设计的必然结果，不是数据偏向。

### 稳健性检验

五组权重下（0.50/0.30/0.20、0.70/0.20/0.10、0.40/0.40/0.20、0.34/0.33/0.33、0.60/0.15/0.25），
与基准的 Spearman 秩相关最低 0.9455，前十重合 6—10 部。

所以结论的写法要克制：**可以说「进前十稳健」，不能说「第几名稳健」。**

### 可迁移的经验

**多个不同量纲的指标相加之前，必须标准化。** 而判断「量纲是否可比」的方法很简单：
把两个量的分布画出来，看取值范围是不是一个数量级。

在这个例子里，R 的取值范围是 [−1, 1]，S 集中在 [0, 0.5]，一看就知道不可比。

## 问题 6：用星级训练情感模型，会让 Q4 变成循环论证

### 现象

这不是运行时的错误，而是一个方案选择上的陷阱。

Q4 要回答「星级与文本情感是否一致」。提高情感模型准确率最直接的办法，
是拿星级当标签训练一个分类器——星级是现成的标签，12,828 条数据，训练集充足。

技术上完全可行，准确率能轻松超过 90%。

### 根因

**如果情感模型是用星级训练出来的，那么它判出来的情感，本质上就是星级的函数。**

再用它去检验「星级与文本是否一致」，等于让模型自己给自己判卷：

```
星级 → 训练情感模型 → 模型输出情感 → 比较「星级 vs 情感」→ 必然高度一致
```

这个推论是重言式，不包含任何关于用户行为的信息。Q4 的所有结论都会失去意义。

### 修法

**情感判定完全不使用星级作为输入。**

- 词典的权重是人工设定的，不是从星级数据里学出来的
- 回退机制用的是 snownlp（电商语料训练的通用模型），也不涉及电影星级
- 唯一用到星级的地方是**评估**（比较 gap），不是在**判定**

### 代价

接受 69.33% 的准确率，而不是 90% 以上。

这个取舍在其他场景下不一定成立。如果研究问题不涉及「星级与文本是否一致」，
比如只是想做情感分类，那用星级训练完全合理，准确率还更高。

**红线只在特定问题下才成立，不是普遍规则。**

### 可迁移的经验

**问自己一句：我的标签是不是从我要检验的那个变量里来的？**

如果是，那这个模型不能用来检验那个变量。这在因果推断里叫「用结果预测结果」，
在机器学习里表现为标签泄漏（label leakage）。

这个检查要放在设计阶段，不是跑完发现结果「太完美」才回头查。

## 问题 7：结构校验失效，255 条不可信记录被判成「信息少」

### 现象

规则适配层的第一版跑完，分类结果和预期不符：

| 标签 | 预期 | 实际 |
|---|---:|---:|
| X（剔除） | 258 | 3 |
| B（低信息量） | 130 | 385 |

X 类从 258 掉到 3，多出来的 255 条去了 B 类。

### 根因

X 类的定义是「字段错位、空文本」。第一版的实现只把**空文本**判为 X。

而那 255 条记录的问题是**字段整体错位**——某一批数据在导出时列顺序错了，
`comment` 列里装的其实是 `time` 的值，`star` 列里装的是别的东西。

这类记录**文本长度不短**（所以不触发「过短」规则），**也不是空文本**（所以不触发 X 规则），
于是落到了内容规则里，被判定为「有一定长度、但看不出明确评价」→ B 类低信息量。

**「不可信」被当成了「信息少」。**

### 修法

把结构校验提到最前面：

```
判定顺序改为：
1. 结构校验（列是否对得上、必要字段是否为空、值域是否合法）→ 不合格判 X
2. 空文本 → X
3. 广告特征 → C
4. 重复检测 → D
5. 长度与要素词判定 → A / B / E
```

修正后 X 类恢复 258 条（255 条结构错位 + 3 条空文本）。

### 为什么这个错误难发现

因为它**不是崩溃，而是一个分类结果**。

程序正常运行，输出了 12,828 条标签，各类占比看起来也合理（B 类才 3%，很正常）。
如果不逐类核对数量，这个错误会一路传到下游：

- 255 条垃圾数据进入情感统计，污染情感均值
- 报告里的「A 类 11,562 条」会是错的

### 可迁移的经验

**「排除」必须优先于「归类」。**

如果一条记录不可信，那么讨论它「内容有没有意义」是无效的——你已经不能相信它的任何一个字段，
包括长度。把不可信的记录先去干净，再在可信的记录上做分类。

这个原则在代码里的落点是把结构校验写成第一个 if，而不是最后一个 else。

## 问题 8：统计表里的「保留评论数」与「占全量比例」互相矛盾

### 现象

`outputs/tables/method_comparison.csv` 长这样：

| 方法 | 保留评论数 | 占全量比例 | 准确率 | F1 |
|---|---:|---:|---:|---:|
| 方法一_基础清洗 | **258** | **0.98** | 0.5167 | 0.6682 |
| 方法二_改进清洗 | **181** | **0.9114** | 0.7333 | 0.7778 |

按比例反算：12,828 × 0.98 = 12,571，12,828 × 0.9114 = 11,691。

但表里写的是 258 和 181。**同一行里两个字段互相矛盾。**

### 根因

看代码就清楚了：

```python
"保留评论数": m.get("保留数", n_base if name.startswith("方法一") else n_impr),
"占全量比例": round((n_base if ... else n_impr) / n_total, 4),
```

而 `保留数` 的定义是：

```python
"保留数": int(y_pred.sum()),    # y_pred 是在 300 条验证集子集上算的
```

**「保留数」是验证集子集的计数（258/181，合计 300 条中的一部分），
而「占全量比例」是拿全量数字算的。**

两个字段来自不同的计算范围，被放在了同一行。

### 为什么这个错误一直没被发现

因为验证集正好是 300 条，而 258 ≈ 12,828 × 0.98 的量级看起来差不多（都是「几百」和「九成多」），
粗看不会觉得别扭。

只有拿计算器反算一次才会发现矛盾。

### 修法

两种改法，各有取舍：

**改法一（推荐）：把字段名写清楚口径。**

```python
"验证集保留数": int(y_pred.sum()),
"全量保留数": n_base,
"占全量比例": round(n_base / n_total, 4),
```

**改法二：加一个断言，让矛盾无法通过。**

```python
assert abs(row["保留评论数"] / n_total - row["占全量比例"]) < 0.01
```

### 可迁移的经验

**字段名里要带口径。** 「保留数」是个歧义词——保留了多少？在哪个范围里保留？
如果字段叫 `验证集保留数` 或 `全量保留数`，这个错误在写下的那一刻就能被发现。

**同一张表里的数字，要能用一两步算出来互相验证。** 如果算不出来，说明口径不一致。

## 汇总：八个问题的共同结构

把上面八个问题放在一起看，能看出一条规律：

| 问题 | 表面看起来 | 实际是什么 | 靠什么发现 |
|---|---|---|---|
| 1 访问受限 | 技术问题 | 合规选择 | 想清楚「数据来源正当性」 |
| 2 模型失效 | 「不相关」的结论 | 工具分辨力不足 | 分组看中位数 |
| 3 回退效果 | 凭印象认定「未触发」 | 前提假设未实测 | 开/关各跑一遍逐条比对 |
| 4 类型消失 | 图上多了几行 | 样本静默丢失 | 看图上出现了不该有的类别 |
| 5 指数失真 | 前十名很像榜单 | 量纲不可比 | 问「这和原来的榜单有什么区别」 |
| 6 循环论证 | 准确率 90% | 标签泄漏 | 问「标签从哪来」 |
| 7 分类错误 | 占比看起来合理 | 顺序错了 | 逐类核对数量 |
| 8 数字矛盾 | 两个数字都合理 | 口径不一致 | 反算验证 |

**八个里有六个的共同点是：结果不报错、看起来合理、必须主动怀疑才能发现。**

这就是为什么 [06 可复用经验](06-lessons.md) 里把「怀疑自己」列为第一条。
